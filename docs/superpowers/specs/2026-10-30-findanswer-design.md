# FindAnswer 设计

## 目标

FindAnswer 是一个以真实资料依据和严格拒答为核心的 RAG 学习网站。本地版保持单用户运行，原始文件、分块和向量索引保存在本机；公开版通过 Qoder Sites 提供共享资料库，让访客无需配置服务即可上传和提问。两个版本都由硅基流动生成向量，由 DeepSeek 仅根据检索到的资料片段生成回答。

## 已确认约束

- 后端使用 Python、FastAPI 和 Chroma，前端使用 React、Vite 和 TypeScript。
- 支持 TXT、Markdown、文字型 PDF；第一版不做 OCR、知识图谱、Agent、多用户和在线账号。
- 有答案时返回真实文件名、页码或分块号及原文；无足够资料时直接说明无法回答，不使用模型常识补答。
- 硅基流动与 DeepSeek 密钥由本机后端写入当前 Windows 用户的凭据管理器；可选环境变量仍用于高级配置，并优先于已保存凭据。
- 密钥不会回显到前端，不会写入浏览器持久化、健康检查或日志；保存前必须通过真实 API 连接测试，成功后立即生效。
- 页面采用父级工作台布局与嵌套子页面；切换时使用短暂、克制的淡入和位移动效。
- 视觉为安静、克制、简约的灰白色资料工作台，不使用浮夸渐变或大面积高饱和色。

## 架构与数据流

1. 上传文件后计算 SHA-256，保存原文件并提取按页文本。
2. 文本按段落和长度分块，保留文件 ID、文件名、页码与块序号。
3. 后端批量调用硅基流动 Embedding API，将向量与原文写入本地 Chroma，文件记录写入 SQLite。
4. 提问时先向量化问题并检索 Top-K，按可配置相似度阈值过滤。
5. 没有有效片段时直接返回统一拒答，不调用 DeepSeek。
6. 有证据时将编号片段发送给 DeepSeek；证据不足时模型返回约定标记，后端转换为统一拒答。
7. 引用由后端映射到真实片段，页面可展开查看原文。

## 页面

- 问答：问题输入、回答/拒答状态、检索片段与来源引用。
- 资料：上传、删除、索引状态、分块预览。
- 模型连接：两个密码输入框分别保存并测试硅基流动与 DeepSeek 密钥，显示配置状态、模型信息和脱敏反馈。
- 父级外壳：侧栏、产品名称、本地状态、子页面出口与路由过渡。

## 本地启动

1. 双击项目根目录的 `FindAnswer.lnk`。
2. 启动器通过命名互斥锁避免连续双击造成重复启动，并检查本机 8000 与 5173 端口上的 FindAnswer 服务。
3. 已运行的服务直接复用，仅启动缺失的一端；前后端均在后台隐藏运行，不就绪时不打开网站。
4. 服务就绪后自动打开 `http://127.0.0.1:5173`。运行日志位于 `.runtime/`，不包含请求中的密钥。
5. `start-dev.bat` 保留为显示命令行窗口的开发备选方式，不再要求创建 `.env`。

## 错误处理与隐私

- 不支持的格式、空文件、重复文件和超过 20 MiB 的文件返回明确错误。
- 上游 API 错误由后端转换为可读的 502 响应，不泄露密钥。
- 只有向量化所需文本和检索命中的片段会发送到对应 API；完整资料库不会发送给 DeepSeek。

## 验证

- 单元测试覆盖分块、低分检索拒答、无结果不调用 DeepSeek、引用映射。
- API 测试覆盖健康状态、空问题校验和拒答响应。
- 前端执行连接表单交互测试、TypeScript 检查与生产构建。
- 启动器测试覆盖复用现有服务、仅启动缺失端、就绪等待、依赖缺失和启动失败。
- 浏览器检查问答、资料、模型连接三个子页面，上传与空状态、无答案展示、来源展开、密钥保存反馈、路由动画和窄屏布局。

## 文件夹批量上传

文件夹上传同时服务于本地版和公开版，并保留“选择文件”入口。

1. 浏览器递归读取所选文件夹及子文件夹，使用浏览器提供的相对路径标识文件，不读取或上传本机绝对路径。
2. 仅处理扩展名为 `.txt`、`.md`、`.markdown`、`.pdf` 且大小不超过 20 MiB 的文件；其他格式和超限文件列入跳过明细。PDF 仍只支持文字型内容，不增加 OCR。
3. 合格文件按相对路径排序，每批最多处理前 100 个；其余文件明确标为“未处理（超过单批上限）”，不得静默忽略。
4. 前端沿用现有单文件上传接口顺序调度，不并发调用模型服务；同一批请求携带相同批次标识，单文件上传视为只有一份文件的批次。上传区域显示当前序号、本批总数、当前文件名和单文件进度。
5. 单个文件失败不中断整批；遇到公开版每日或总量上限时停止后续请求，将剩余文件标为未处理。
6. 完成后汇总成功、重复、跳过、未处理和失败数量，并提供每个失败文件的原因。重复判断继续使用文件内容 SHA-256。

## 公开版目标与边界

- 所有访客共用同一个资料库，均可查看共享资料、上传和提问，不引入在线账号。
- 访客不能删除资料，也不能查看、修改或测试模型密钥。前端隐藏管理入口，后端必须独立拒绝这些操作。
- 本地版继续使用本机文件、SQLite、Chroma 和 Windows 凭据管理器；公开版不得依赖这些本机资源，也不要求用户电脑保持开机。
- 共享库原文件、资料元数据和检索片段对所有访客可见。上传内容会按 RAG 流程发送至硅基流动，问题及命中片段会发送至 DeepSeek，页面必须持续提示不得上传隐私或机密资料。
- 公开版不保存访客问答历史，不改变真实引用、证据不足拒答和无有效检索依据时不调用 DeepSeek 的原则。

## 公开版托管架构

1. **Qoder Sites 前端**：托管公开网站，并通过同源 API 与托管后端通信。
2. **Sites Functions**：承载上传、资料读取、检索和问答接口，执行格式校验、权限、配额、并发控制及模型调用。
3. **Sites Storage**：保存上传的原始文件，不使用 Function 实例的临时文件作为持久化存储。
4. **Sites Database**：保存资料记录、原文分块、向量、内容哈希、上传配额和预留记录；检索保持余弦相似度、Top-K 和可配置阈值语义。
5. **Sites Secrets**：在 Site Settings 中配置硅基流动与 DeepSeek 密钥，只允许服务端读取。密钥值不得写入聊天、代码、前端、日志或健康检查。
6. **运行模式**：后端向前端返回本地或公开模式及对应能力。公开版的删除和连接修改接口直接拒绝，不能仅依赖界面隐藏。

## 公开版上传与配额

1. 服务端重新校验文件格式、大小、单批上限、每日 IP 限额和共享库容量，不信任前端检查结果。服务端按批次标识记录合格文件数并拒绝同批第 101 个文件；更换批次不能绕过每日或总量限制。
2. 客户端 IP 只采用托管平台提供的可信来源，不直接信任调用方可伪造的转发请求头；无法可靠确定客户端 IP 时拒绝公开上传，但可继续提供问答。
3. 每个 IP 每个北京时间自然日最多成功上传 30 份新资料，共享库最多保存 500 份资料；单批最多 100 个合格文件不放宽每日或总量限制。
4. 已存在相同 SHA-256 的资料直接返回已有记录，不重复存储或调用 Embedding，也不消耗每日新增额度。只有成功入库的新资料最终计入每日和总量，失败文件不占额度。
5. 上传前先通过数据库原子操作预留一个每日额度及容量位置，再执行原文件存储、文本提取、分块和 Embedding。预留期间该位置计入占用，成功后确认，失败后释放。
6. 内容哈希唯一约束与原子预留共同防止并发请求绕过限制；相同内容同时上传时只保留一份，其余请求按重复资料处理。
7. 异常中断留下的超时预留由后续上传流程回收。存储、模型或数据库任一步失败时清理该文件的中间数据，网络错误不自动重试上传。
8. 页面显示共享库已用容量和当前 IP 当日剩余上传数；达到每日或总量上限时停止本批后续上传并说明原因。

## 公开版问答数据流

1. 将访客问题发送至硅基流动生成查询向量，再检索共享库中的真实分块。
2. 没有达到相似度阈值的有效片段时直接返回统一拒答，不调用 DeepSeek。
3. 有证据时才将问题和编号片段发送至 DeepSeek；证据不足或模型返回无效、越界、缺失、混合无效引用时，后端仍将整答转换为拒答。
4. 后端把有效引用编号映射到实际存储的文件、页码和分块，绝不采用模型自行生成的文件名或来源。
5. 问题和命中片段只用于当次请求，公开版不写入问答历史。

## 公开版异常处理与验收

- 单个文件返回明确的成功、重复或失败结果；批量界面保留跳过、未处理和失败明细。达到全局上限时不继续发送无效请求。
- 上游模型错误、存储错误和配额错误使用可读且脱敏的响应，不暴露 Secrets、堆栈或其他访客数据。
- 自动化测试覆盖混合格式、嵌套文件夹、超过 100 个文件、部分失败、重复内容和上传进度。
- 后端使用模拟模型服务验证每日 30、总量 500、单批 100、并发上传、相同内容竞争、伪造 IP、访客权限、失败释放及超时预留回收，不使用真实 API 密钥。
- 完整回归本地版的分块、检索、严格拒答、真实引用、连接配置和一键启动，确保公开版适配不改变本地使用方式。
- 发布前先以无隐私测试资料验证上传、检索、引用、拒答和跨访客共享，再配置正式 Secrets 并发布公开地址。
- 发布后检查公开权限、限额、错误反馈和窄屏布局，并确认响应、日志及浏览器存储均不泄露密钥。
